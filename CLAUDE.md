# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Personal dotfiles repo for macOS (Apple Silicon + Intel), Ubuntu Desktop, and Linux (GitHub Codespaces). Uses plain copy scripts — no symlinks, no stow. General dotfiles live in `config/` mirroring `~/` structure; isolated machine profiles live under `profiles/`.

## Key Scripts

- `./linux-desktop.sh` — Dedicated Ubuntu Desktop home-profile installer.
  Linux-only and explicitly allowlisted; supports `--dry-run`, preserves
  timestamped backups under `${XDG_STATE_HOME:-$HOME/.local/state}/linux-setup/backups/`, and uses no
  `sudo`, package manager, network call, shell change, or Git pull. It is the
  only dotfiles entry point that `nathanialhenniges/linux-setup` may invoke.
  Keep `server.sh`, `server-dev.sh`, `lib/bootstrap.sh`, `config/server/**`, and
  `config/agent/**` frozen and independent from this path.
- `./update.sh` — Guarded updater for an existing macOS or Ubuntu Desktop
  checkout. It verifies the exact repository origin, `main`, and a clean
  worktree; fetches and merges only with `--ff-only`; never commits or pushes;
  then dispatches to `install.sh --apply-only` on macOS or only
  `linux-desktop.sh` on Linux. `--dry-run` performs no fetch or writes.
- `./install.sh` — Full bootstrap for a new machine: installs Homebrew + Brewfile (macOS) or apt essentials (Linux), Oh My Zsh + plugins (fzf-tab, zsh-autosuggestions, zsh-syntax-highlighting), copies dotfiles from `config/` to `~` (skips `config/server/`), and installs the latest Node.js via fnm.
  Its macOS-only `--apply-only [--dry-run]` route uses a fixed desktop-file
  allowlist, preserves the first adjacent `.backup`, and skips all package,
  Homebrew, plugin, and Node bootstrap work.
- `./sync.sh` — Copies allowlisted dotfiles from `~` back into `config/` and regenerates the Brewfile. **macOS only** (uses `brew bundle dump`). It deliberately skips `.gitconfig` and `.npmrc`; review those manually so machine IDs or registry tokens cannot enter this public repo.
- `./server.sh` — Standalone bootstrap for remote Linux servers. Clones the repo, installs zsh + essentials via apt, Oh My Zsh + plugins, copies configs from `config/server/` to `~`, and switches default shell to zsh. Designed to run as a one-liner: `bash <(curl -fsSL ...)`. Sources shared helpers from `lib/bootstrap.sh`.
- `./server-dev.sh` — Linux-only dev-server bootstrap. **Environment only — it does NOT harden the machine.** Does everything `server.sh` does (via the same `lib/bootstrap.sh` helpers), then installs dev tooling: fnm + latest LTS Node, Docker (official `get.docker.com` script, adds user to the docker group), and dev CLIs (gh, direnv, bun, go, build-essential, jq, eza, btop). `install_extra_clis` then adds the MacBook-parity set — ncdu, gnupg, ffmpeg, rclone via apt; yt-dlp, fastfetch, awscli and act via arch-aware downloads; terraform via HashiCorp's apt repo (same keyring pattern as gh). **Every one of those is best-effort** — a release 404 must never abort a provisioning run, so each step falls back to a `substep` note. Downloads branch on `dpkg --print-architecture` and the projects disagree on naming (`aarch64` vs `amd64` vs `x86_64` vs `_linux`). **`ansible` is deliberately excluded** — `chi-01` must never enter the Ansible inventory and having the tool on the box invites the no-`--limit` run that rule exists to prevent. `restore_docs` runs last and calls `unminimize` (Ubuntu cloud images ship with no man pages), skipped if `/usr/share/man/man1` is already populated. **It opens a port if left alone:** `unminimize` installs `ubuntu-server` → `nfs-common` → `rpcbind`, which listens on `0.0.0.0:111`, so the function disables `rpcbind.socket` immediately after. Likewise `--chrome` on 24.04 installs the Chromium *snap*, which pulls the **cups snap** listening on `0.0.0.0:631` — `install_chrome` disables it. Both were found by auditing `ss -tlnp` on chi-01, not by reading the installers. Creates a basic home layout (`~/Developer`, `~/Downloads`; idempotent). Does NOT create the user (create the sudo account + add your key first). Optional flags: `--ai` installs the Claude Code (`@anthropic-ai/claude-code`) + Codex (`@openai/codex`) CLIs as npm globals plus `bubblewrap` (Codex Linux sandbox); `--pnpm` installs pnpm (both opt-in, run after fnm/Node via the shared `npm_global_cmd` helper). `--agent-setup` (implies `--ai`) replicates the agent config from `config/agent/`: curated `~/.claude/settings.json` (no machine-specific hooks/statusline), copies the Claude and custom Codex skill packs to `~/.claude/skills/` and `~/.codex/skills/`, recreates the shared `~/.agents/skills/` index, adds the shared GitHub plugin marketplaces + installs the plugin set into BOTH Claude Code (`claude plugin ...`) and Codex (`codex plugin ...`) from the same `AGENT_MARKETPLACES`/`AGENT_PLUGINS` arrays, writes a Linux-safe `~/.codex/config.toml`, and pre-registers the Atlassian (Jira) MCP for both (OAuth login is manual — see `docs/jira-mcp-setup.md`). Vendored agent assets live in `config/agent/{claude,codex}/`. `--chrome` installs a headless-capable browser for automation/screenshots (Google Chrome on amd64, Chromium on other arches, + fonts-liberation) — it installs the browser ONLY; a browser MCP (`chrome-devtools-mcp`) is NOT auto-registered and must be added manually to Claude Code and Codex before either can drive it. `-h/--help` prints an embedded usage block (must NOT be self-grepped from `$0` — under `bash <(curl ...)` that pipe is already consumed and prints nothing). One-liner: `bash <(curl -fsSL ...server-dev.sh) [--ai] [--pnpm] [--agent-setup] [--chrome]`. Exits early on macOS. gh login stays manual (interactive + token-scoped).
  - **`--agent-setup-only` re-runs the agent step alone** (implies `--agent-setup`): pulls the dotfiles repo, calls `agent_setup`, exits before `create_home_dirs` — no apt, Docker, chsh or dotfile copies. Use it to retry failed plugin installs or pick up a newly-added plugin. It calls `activate_existing_node` first because it skips `install_fnm_node`, and on a provisioned box the toolchain is activated from `.zshrc` — under bash `claude` does not resolve, so without it `agent_setup` would reinstall CLIs that are already there.
  - **Plugin installs need no Claude Code login.** Marketplace add is `git clone`, install is a file copy; nothing hits the Anthropic API. Verified with an unauthenticated `CLAUDE_CONFIG_DIR`. Do not "fix" a failing plugin install by adding a login step. Conversely, `settings.json` `enabledPlugins` alone does NOT install anything — `claude plugin list` on a config dir holding only settings.json reports none — so the install loop is not redundant with the declarative config.
  - **Plugin marketplace aliases are not repo names.** `AGENT_MARKETPLACES` entries are `owner/repo=alias`, where the alias is the `name` field in that repo's `.claude-plugin/marketplace.json` — `expo/skills` registers as `expo-plugins`. `agent_plugin_preflight` checks every `AGENT_PLUGINS` `@alias` against that set before installing. Keep `config/agent/claude/settings.json` `enabledPlugins` / `extraKnownMarketplaces` in step with the arrays; `tests/test_agent_plugin_arrays.sh` fails if they drift.
  - **Plugin steps must stay loud.** They run through `agent_try`, which separates "already present" from a real failure, prints the actual error, and lists every failure at the end of `--agent-setup`. Do NOT go back to `&>/dev/null || substep "already installed or unavailable"` — that wording made a failed marketplace add look like a no-op, and chi-01 provisioned with zero expo plugins while the log looked clean.
  - **`expo/skills` needs the submodule fallback (2026-07-29).** It carries a submodule pointing at the private `expo/eval-experiments` (added in expo/skills#105 for Expo's own eval CI). Claude Code clones marketplaces with `--recurse-submodules` so the add aborts; codex doesn't recurse, which is why codex installs it fine. Upstream: expo/skills#110. `marketplace_add_local` retries any failed add by cloning `--no-recurse-submodules` into `~/.local/share/claude-marketplaces/` and adding that DIRECTORY — same alias, same plugins — then calls `agent_forget_failure` so the summary doesn't report a step that was repaired. It runs only after the normal add fails, so it self-disables when upstream fixes this. `extraKnownMarketplaces` keeps the GitHub source on purpose: that's the intent, the clone is the workaround. Do NOT "simplify" this by copying `plugins/expo/skills` into `~/.claude/skills` — the plugin also ships `hooks/`, `agents/` and an MCP (`https://mcp.expo.dev/mcp`), and a skills-only copy silently drops them. Its PostHog `skill_invoked` hook is opt-in and off by default.
  - **`agent_try` returns non-zero on a real failure** (0 for success and for already-present). `marketplace_add_local` hangs off that status. Every call site that does not handle it needs `|| true`, or `set -e` aborts the run mid-setup.
  - **Hardening moved out (repo boundary).** sshd, UFW, sysctl, fail2ban, unattended-upgrades and `--hostname` used to live here and are now in `server-dev-setup.sh` in the PRIVATE `MrDemonWolf/server-setup` repo, along with `tests/test_key_guard.sh` and `tests/test_hosts_rewrite.sh`. Two reasons: server devops is not dotfiles, and this repo is public. **Do not add hardening back here** — if a box needs securing, that belongs in the private repo, which hardens BEFORE handing off to this script.
  - `--hostname` and `--no-firewall` are now rejected with an explanatory error rather than silently ignored. Being quietly dropped is how you end up believing a box was hardened.
  - **Docker is the sharp edge this script leaves behind.** It installs Docker, whose published ports bypass a host firewall (they land in the `nat` table below INPUT), and `ufw status` will not show it. The private repo applies `ufw-docker` AFTER this handoff — that ordering is load-bearing, because ufw-docker's unit declares `Requires=docker.service`.
- `lib/bootstrap.sh` — Shared bootstrap helper functions (`log`, `substep`, `detect_os`, `install_base_packages`, `install_oh_my_zsh`, `install_zsh_plugins`, `install_oh_my_posh`, `copy_configs`, `set_default_shell`) sourced by `server.sh` and `server-dev.sh`. Add new shared setup steps here rather than duplicating across scripts. **Not** copied to `~` (lives outside `config/`).
- `./sharedhosting.sh` — Bootstrap for shared hosting (no root). Copies configs from `config/sharedhosting/` (`.bashrc`, `.aliases`). Pure bash, no package installs.

## Architecture

- `profiles/linux-desktop/` — Separate, portable Ubuntu Desktop profile. It
  deliberately lives outside `config/` so the broad-copy Mac and Codespaces
  installers cannot discover it. It must
  not source or copy the server, devbox, agent, shared-hosting, Mac-only alias,
  scripts, or Git-signing configuration.
- `config/` — All dotfiles, mirroring home directory structure. `config/.zshrc` becomes `~/.zshrc`, `config/.config/ohmyposh/` becomes `~/.config/ohmyposh/`, etc. `config/server/` holds server-only configs (minimal `.zshrc`, `.aliases`) and is excluded from `install.sh`. `config/sharedhosting/` holds shared hosting configs (`.bashrc`, `.aliases`) used by `sharedhosting.sh`.
- **Exception:** Ghostty config lives in `config/.config/ghostty/` in the repo but `install.sh` maps it to `~/Library/Application Support/com.mitchellh.ghostty/` on macOS (where Ghostty actually reads it). `sync.sh` pulls from that Application Support path.
- The isolated Linux Ghostty profile ports only settings supported on Ubuntu GNOME, uses the CaskaydiaCove Nerd Font installed by `linux-setup`, and launches `/usr/bin/zsh` directly. Do not copy macOS-only titlebar, P3, blur, or Command-key settings into it.
- `Brewfile` — Homebrew packages, casks, Mac App Store apps, and VS Code extensions. Auto-generated by `sync.sh`.
- `.zprofile` detects Apple Silicon (`/opt/homebrew`) vs Intel (`/usr/local`) Homebrew paths.
- `.zshrc` and `.zprofile` use `uname` checks (`Darwin` vs Linux) to conditionally run macOS-specific blocks (Homebrew paths, Android SDK, Oh My Posh, fnm, etc.).

## Conventions

- When adding a new dotfile: add it to the `files` array in `sync.sh`, then run `./sync.sh`. For nested paths under `~/.config/`, add an explicit `cp` command in the nested config section of `sync.sh`.
- Custom scripts live in `~/.scripts/` (hidden folder) and are tracked in `config/.scripts/`. `install.sh` copies them to `~/.scripts/` and makes them executable. `sync.sh` pulls them back.
- `~/.secrets` holds API keys/tokens and is gitignored — never commit secrets. Secrets are sourced at the end of `.zshrc`.
- `*.backup` files are gitignored (created by `install.sh` when overwriting existing dotfiles).
- Shell config assumes zsh with Oh My Zsh. Plugins: git, fzf-tab, zsh-autosuggestions, zsh-syntax-highlighting.
- `.zshrc` uses direnv for per-directory environment variables (`eval "$(direnv hook zsh)"`).
- Ghostty config uses a Liquid Glass theme with transparency and blur (`background-opacity: 0.90`, `background-blur-radius: 90`).
